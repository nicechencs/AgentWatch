# ADR-0012 不存内容，写入前脱敏

> 状态：已接受
> 最后更新：2026-10-06
> 关联：REQ-07、[security-privacy](../01-architecture/security-privacy.md)

## 背景

审计数据本身就极其敏感：它包含凭证文件路径、命令行里的 token、带签名的 URL。如果审计工具自己变成了凭证仓库，就是新的风险点。

## 决策

1. **永不存储**：文件内容、HTTP 请求和响应 body、`Authorization`/`Cookie`/`Set-Cookie`/`Proxy-Authorization` 头的值、环境变量的值。环境变量只保留变量名列表，并且默认不采集。
2. **在管道中写入之前脱敏**（不是展示时才脱敏）：
   - argv 中形如 `--token=`、`-p`、`password=` 的值；
   - URL 查询参数中的 `token|key|secret|sig|signature|password|auth|code`；
   - URL 里的 userinfo（`user:pass@`）；
   - 已知格式的密钥：AWS AK、GitHub token、`sk-` 开头的 key、JWT 等。
   - 脱敏后保留 `<redacted:len=40:hash=ab12>` 这样的短哈希（加盐），以便关联同一个值。
3. 为了做内容匹配，文件和 body 的分块哈希只在内存中存在，存活时间有限；只有“是否匹配”的结论写入数据库。
4. 敏感路径规则只用来高亮，不会触发额外读取。例外是内容匹配功能：在代理模式下，如果用户启用，就对敏感文件计算分块哈希。
5. 脱敏规则可以增加，但**内置规则不能通过配置关闭**。特权用户确实需要时，可以用 `--unsafe-no-redact` 标志关闭，但会话会被永久标记。

## 备选方案

| 方案 | 结论 |
|---|---|
| 全部存下来，展示时再脱敏 | 数据库一旦泄露，就是完整的凭证。不选 |
| 加密后存内容 | 复杂度高、收益小，违背了最小化原则 |

## 后果

- 正面：导出的文件可以相对安全地分享。
- 代价：事后无法还原被脱敏的值；脱敏会有误报，会影响排障。脱敏规则需要单元测试覆盖。
