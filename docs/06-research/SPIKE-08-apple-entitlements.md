# SPIKE-08 Apple ES/NE 授权申请与原生原型

> 状态：未开始
> 最后更新：2026-10-06
> 关联：ADR-0009、CAP-PROC-01、CAP-NET-01~03、CAP-PRIV-01、[macos.md §2](../02-platforms/macos.md)
> 时间盒：申请 0.5 人天（P0 第 1 周）+ 原型 3 人天（授权下来后，最晚 P4）
> 负责人：

## 1. 问题

1. ES client 授权和 NE 内容过滤器（系统扩展）授权有没有批下来？各用了多久？审核问了哪些问题？
2. 以 Developer ID 分发时，NE 内容过滤器是否需要单独申请？
3. ES client 能否以普通的 LaunchDaemon 形式运行（可执行文件在 app bundle 内，带 provisioning profile）？还是必须做成系统扩展？
4. Rust 的 ES client 与 Swift 的 NE 扩展之间，XPC 通信怎么做最简单、最可维护？
5. NE 对全部流量做 peek 统计字节的性能代价是多少（吞吐和 CPU）？有没有更轻的办法拿到每条流的字节总数？
6. 签名和公证能否在 GitHub Actions 上全自动完成？

## 2. 假设

- ES 授权在 2–6 周内获批；NE 内容过滤器以 Developer ID 分发时可以自助勾选。
- peek 的代价可以接受。

## 3. 方法

1. P0 第 1 周：提交申请。申请理由的要点：本地审计 AI Agent；只用 NOTIFY；不外发数据；开源。把提交内容存档到 `assets/SPIKE-08/`。
2. 等待审批期间，在关闭 SIP 的专用测试机上用开发签名做原型。
3. 拿到授权后，在开启 SIP 的机器上验证完整的安装、批准、卸载流程。
- 代码位置：`spikes/SPIKE-08/`，之后迁移到 `macos-ext/`。

## 4. 通过标准

| 指标 | 通过 | 不通过时的预案 |
|---|---|---|
| 授权是否获批 | 两项都获批 | 产品长期留在 M1，并在 UI 中标注；重新评估 ADR-0009 |
| NE 对吞吐的影响 | 下载吞吐下降 <10% | 只统计范围内的进程，其余流量直接放行 |
| CI 签名和公证 | 自动完成 | 改为本地手动发布 |
