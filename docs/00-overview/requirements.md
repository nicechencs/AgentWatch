# 需求清单

> 状态：草案
> 最后更新：2026-10-07
> 关联：[vision](vision.md)、[roadmap](../04-plan/roadmap.md)、[capability-matrix](../02-platforms/capability-matrix.md)

本文件是需求的**唯一定义处**。任务卡、ADR、测试用例通过编号引用这里的条目。

优先级：**M** 必须（MVP 前完成）、**S** 应该（1.0 前完成）、**C** 可选。

## 1. 功能需求

### REQ-01 跨平台支持（M）
支持 Windows 10 1909+/11、macOS 13+、Linux（内核 ≥5.8 带 BTF 为完整能力；更低版本降级运行）。
- 验收：三平台各有安装包，能完成 REQ-02~05 的基本流程；能力差异在 UI 和 `aw doctor` 中如实展示。

### REQ-02 进程选择与范围追踪（M）
- REQ-02.1 启动模式：`aw run -- <cmd>` 从工具启动程序，自动纳入全部后代进程。
- REQ-02.2 附着模式：`aw attach --pid <pid>` 选择正在运行的进程（UI 中提供可搜索的进程列表）。
- REQ-02.3 关联子进程及其调用的其他程序，形成进程树；记录 exec 链（父 → 子 → 孙）。
- REQ-02.4 识别“归属链路中断”（委托给已有守护进程、`systemd-run`/`launchd` 等），如实标注而不硬套归属。
- 验收：模拟器剧本中 3 层以上派生的进程全部被纳入会话；附着前已存在的子进程也被纳入。

### REQ-03 文件访问记录（M）
- REQ-03.1 记录打开（含读/写意图）、读取（次数与字节）、修改、创建、删除、重命名。
- REQ-03.2 记录执行的命令：可执行路径、argv、工作目录、父进程、退出码。
- REQ-03.3 同一句柄的连续读写聚合为一条记录。
- REQ-03.4 平台无法提供的字段（如 macOS 读取字节数）标为 `NA` 并附原因。
- 验收：模拟器诱饵文件的读/写/删/改名事件召回率 ≥95%（E1 平台）。

### REQ-04 网络流量统计（M）
- REQ-04.1 按进程、进程树（会话/Agent）、域名、目标 IP 统计上传与下载字节。
- REQ-04.2 显示协议、本地地址与端口、目标地址与端口、连接起止时间。
- REQ-04.3 通过 DNS 观测和 SNI 将 IP 映射到域名，并标注映射来源。
- REQ-04.4 在代理模式下记录完整 URL、方法、状态码、请求/响应 body 字节；未经代理的连接标为“直连”。
- 验收：向本地测试服务器上传已知字节数，统计误差 <5%（E1 采集）；S 级采样采集（如 macOS nettop）放宽到 <15%，并在 UI/CLI 标注；代理模式下 URL 准确。

### REQ-05 时间线、查询与导出（M）
- REQ-05.1 会话活动时间线，文件、进程、网络事件在同一时间轴上。
- REQ-05.2 历史会话列表与查询；按进程、事件类型、路径 glob、域名、时间范围、证据等级筛选。
- REQ-05.3 导出 JSONL、CSV；导出内容同样经过脱敏。
- REQ-05.4 从任一文件事件跳转到相邻时间窗口内的网络事件（反之亦然）。
- 验收：100 万条事件的会话，常用筛选 <300 ms。

### REQ-06 证据与推测分离（M）
- REQ-06.1 每条记录带证据等级与数据来源。
- REQ-06.2 关联结论只能是“推测”，使用固定措辞，不得将“读取文件后联网”表述为“上传了文件”。
- REQ-06.3 唯一的升级路径：代理模式下请求体分块哈希与文件分块哈希匹配，标为“内容匹配证据”。
- REQ-06.4 采集缺口（丢事件、权限不足、采集器重启）作为一等数据记录并在时间线上展示。
- 验收：关联规则的输出措辞由测试断言。

### REQ-07 本地保存与敏感信息保护（M）
- REQ-07.1 默认只存本地，无任何遥测或外发。
- REQ-07.2 默认不存文件内容、HTTP body、`Authorization`/`Cookie` 头。
- REQ-07.3 命令行、URL 查询参数、环境变量中的凭证自动脱敏。
- REQ-07.4 敏感路径规则命中时高亮提示，不额外读取该文件内容。
- REQ-07.5 数据库文件权限仅限当前用户与管理员；可选加密（C）。
- REQ-07.6 本地 API 只监听回环地址，需随机 token 鉴权。

### REQ-08 GitHub 管理（M）
需求、代码、任务、发布均在 GitHub 管理；文档中的任务卡可同步为 Issue。详见 [github-workflow](../05-dev/github-workflow.md)。

### REQ-09 Agent 识别与自报告接入（S）
识别常见 AI Agent（Claude Code、Codex CLI、Cursor、Aider 等）的进程组；接入 Agent 的 hooks / 遥测作为 E3 数据。

### REQ-10 规则与告警（C）
可配置规则（如“Agent 读取 `~/.ssh` 后 10 秒内有外发流量”），命中时生成提示，仍按推测措辞。

### REQ-11 Agent 间通信监控（S）
同时监控多个 Agent（主 Agent、子 Agent、MCP server、独立启动的 Agent）之间的通信。详见 [inter-agent-communication](../01-architecture/inter-agent-communication.md)。
- REQ-11.1 识别会话内的 Agent 实例及其角色（主 Agent / 子 Agent / MCP server）；识别结果本身带证据等级。
- REQ-11.2 配对本机 IPC（管道、Unix socket、命名管道、回环）的两端进程并统计字节数；平台不可得的字段标为 NA。
- REQ-11.3 启动模式下可选记录 MCP 等协议的 method、工具名、字节数和耗时；不存参数和结果内容。
- REQ-11.4 监控组：把独立启动的多个会话组合在一起，配对组内会话之间的通道。
- REQ-11.5 委托链路：从任一事件回溯到触发它的 Agent；每一跳标注等级，整条链取最弱一跳；共享文件关联只能是推测。
- 验收：`multi_agent` 剧本在 Linux 上通道配对召回率 ≥95%、字节误差 <5%；链路措辞由测试断言。

## 2. 非功能需求

| 编号 | 项目 | 目标 | 优先级 |
|---|---|---|---|
| NFR-01 | 空闲 CPU | 无监控会话时 <0.5%；监控典型 Agent 会话时 <3%（单核） | M |
| NFR-02 | 内存 | daemon 常驻 <60 MB | M |
| NFR-03 | 磁盘 | 1 小时典型 Agent 会话 <50 MB；默认上限 2 GB / 30 天，自动清理 | M |
| NFR-04 | 安装体积 | 单平台安装包 <25 MB | S |
| NFR-05 | 事件延迟 | 事件从发生到可查询 <2 s | S |
| NFR-06 | 可靠性 | 采集器崩溃自动重启；丢失必须记入缺口 | M |
| NFR-07 | 可维护性 | 平台无关逻辑 ≥70% 代码量，可在无特权环境下测试 | S |
| NFR-08 | 构建速度 | 增量 `cargo check` <10 s；CI 全矩阵 <20 min | S |
| NFR-09 | 可卸载 | 卸载后不留 CA 证书、系统扩展、服务 | M |

## 3. 非目标

- 不对抗具有同等或更高权限、刻意规避监控的恶意程序。
- 不做远程/集中式监控（多机汇聚可作为未来扩展，不在 1.0 范围；可选的离线合并 `aw merge` 见 REQ-11 的设计文档 §9）。
- 不做阻断/拦截（只审计）；拦截能力可在 P5 之后评估。
- 不保存或分析文件内容和流量内容（REQ-06.3 的本地哈希比对除外）。
