# 愿景与范围

> 状态：草案
> 最后更新：2026-10-06
> 关联：[requirements](requirements.md)、[architecture](../01-architecture/architecture.md)、[evidence-model](../01-architecture/evidence-model.md)

## 1. 一句话定位

AgentWatch 是一个**本地运行、跨平台**的进程行为审计工具。它回答一个问题：**“这个 AI Agent 在我的机器上到底做了什么？”** 具体来说，它碰过哪些文件、执行了哪些命令、连过哪些地址、收发了多少数据。每个结论都标明证据等级。

## 2. 背景

AI 编程 Agent（Claude Code、Codex CLI、Cursor、Aider 等）在用户权限下自主运行 shell、读写文件、访问网络。现有手段各有缺口：

| 现有手段 | 问题 |
|---|---|
| Agent 自己的日志 / transcript | 自报告，可能不完整；子进程的行为看不到 |
| 系统自带工具（Process Monitor、fs_usage、strace） | 单平台；事件量巨大，没有按会话聚合；没有网络到文件的关联视图 |
| EDR / 企业安全产品 | 重、贵、面向企业；不针对“一次 Agent 会话”这个粒度 |
| 抓包工具（Wireshark、mitmproxy） | 不知道流量属于哪个进程；需要手工关联 |

AgentWatch 把这些能力收敛到“**一次会话 + 一棵进程树**”的视角下，并且在结论上保持克制：看到的才说看到，推测的明确写推测。

## 3. 目标

1. **G1 按会话完整还原**：从工具启动或附着到某个进程后，进程树中的 exec、文件访问、网络连接都归到同一个会话下（REQ-02、REQ-03、REQ-04）。
2. **G2 如实**：每条记录都有证据等级（[evidence-model](../01-architecture/evidence-model.md)）；拿不到的写“不可得”并附原因，不拿推测充当事实（REQ-06）。
3. **G3 便于关联**：文件事件和网络事件在同一条时间轴上，可以互相跳转、筛选、导出（REQ-05）。
4. **G4 本地且安全**：数据不出本机；默认不存内容；凭证自动脱敏（REQ-07）。
5. **G5 轻量**：常驻开销小，可以在开发机上长期开着（NFR-01~04）。

## 4. 非目标

以 [requirements §3](requirements.md#3-非目标) 为准，摘要如下：
- 不对抗刻意规避监控、拥有同等或更高权限的恶意程序；
- 不做集中式 / 多机监控；
- 不做拦截或阻断（1.0 之前只审计）；
- 不保存文件内容和流量内容。

## 5. 目标用户

| 用户 | 诉求 | 典型使用方式 |
|---|---|---|
| 个人开发者 | 放心让 Agent 自主跑；事后能查证 | `aw run -- claude`，结束后看 UI |
| 安全 / 合规人员 | 评估某个 Agent 是否能进入团队流程 | 跑标准任务集，导出报告存档 |
| Agent 开发者 | 调试自家 Agent 的工具调用和网络行为 | 代理模式 + E3 自报告对照 |
| 研究者 | 研究 Agent 的行为模式 | 批量导出 JSONL 做离线分析 |

## 6. 典型场景

### 场景 1：审计一次 Claude Code 会话是否外发凭证

1. 用户执行 `aw run --agent claude --proxy -- claude`。
2. Agent 运行中执行了 `cat ~/.ssh/id_rsa`（子进程 `bash` → `cat`），随后 `node` 向 `api.anthropic.com` 发起请求。
3. 会话结束后，用户在 UI 的“发现”页看到：
   - 【E1】`cat`(pid 5120) 读取 `~/.ssh/id_rsa`，412 B，命中敏感路径规则 `ssh-keys`；
   - 【推测·时序相关】3.1 秒后 `node`(4412) 向 api.anthropic.com:443 发送 5.2 KB；
   - 代理模式下请求体分块哈希**未匹配**该文件，因此结论保持“推测”，并写明“无内容级证据表明该文件被上传”。
4. 用户点击该发现，跳转到时间线上前后 10 秒的窗口，看到完整的进程链和 URL。

### 场景 2：附着到一个已经在跑的 Agent

1. 用户在 UI 的进程选择器中搜索 `cursor`，选中主进程，勾选“包含已有子进程”。
2. AgentWatch 做一次进程树快照，把已有后代纳入会话，之后跟踪新的 fork/exec。
3. 附着前已经建立的连接只能从附着时刻开始计数，UI 上标为“附着前已存在，字节数不完整”。

### 场景 3：比较两个 Agent 在同一任务上的行为

1. 安全人员在干净的仓库副本里，分别用两个 Agent 完成同一个任务。
2. 导出两份会话的 JSONL，或在 UI 中并排看“会话概览”：访问的文件数、目录分布、外联域名、上传总量。
3. 把差异附到评估报告里。

### 场景 4：排查 Agent 为什么下载了大量数据

1. 在“网络”页按域名分组，按下载量排序，发现 `registry.npmjs.org` 下载了 380 MB。
2. 展开后看到流量来自 `npm install`（父进程链：`claude` → `bash` → `npm`），并显示对应的命令行。

### 场景 5：macOS 上没有系统扩展授权时的降级使用

1. 用户在 macOS 上首次运行，`aw doctor` 报告：未安装 ES/NE 扩展，使用 eslogger + nettop 降级模式。
2. 文件读取字节数显示为“不可得（macOS ES 无 read 事件）”；网络字节标为 S 级（采样），并提示短连接可能遗漏。
3. 用户仍然能看到完整的进程树和文件打开/修改/删除记录。

## 7. 成功标准（1.0）

- 在行为模拟器（`sim/`）的标准剧本上，三平台 E1 能力项的召回率 ≥95%；
- 由真实用户用 Claude Code 跑 1 小时会话，能在 5 分钟内回答“它读了哪些敏感文件、向哪些域名发了多少数据”；
- 所有关联类结论都通过措辞测试（见 [evidence-model §5](../01-architecture/evidence-model.md#5-固定措辞模板)）。
