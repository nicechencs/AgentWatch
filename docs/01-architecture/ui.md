# Web UI 设计

> 状态：草案
> 最后更新：2026-10-07
> 关联：REQ-02、REQ-05、REQ-06、REQ-11、[ADR-0002](../03-adr/0002-embedded-web-ui.md)、[api-and-cli](api-and-cli.md)、[evidence-model §4](evidence-model.md#4-展示样式)、[inter-agent-communication §8](inter-agent-communication.md#8-cli-与-ui)

## 1. 技术与约束

- **技术栈**：
  - React 18 + TypeScript + Vite，路由用 TanStack Router，数据层用 TanStack Query；
  - 表格用 TanStack Table，配合 `@tanstack/react-virtual` 做虚拟滚动；
  - 图表用 ECharts，仅按需引入时间轴、堆叠面积图、柱状图。
- **样式**：Tailwind CSS，支持浅色和深色主题。不引入大型组件库，只按需使用 Radix 的无样式组件。
- **打包**：产物由 `rust-embed` 嵌入 `aw-daemon`。目标是 gzip 后 <1.5 MB。
- **离线**：不加载任何外部资源，包括字体、CDN 和统计脚本。CSP 设为 `default-src 'self'`。
- **i18n**：支持 zh / en。文案放在 `ui/src/i18n/*.json`，由 CI 跑禁用词检查（见 evidence-model §7）。
- **大数据**：一切列表都用服务端分页加虚拟滚动，前端不一次性加载超过 2000 行。

## 2. 信息架构

```
/                         → 会话列表
/new                      → 新建会话（启动 / 附着）
/s/:sid                   → 会话概览
/s/:sid/timeline          → 时间线
/s/:sid/processes         → 进程树
/s/:sid/files             → 文件
/s/:sid/network           → 网络
/s/:sid/http              → HTTP 请求（仅代理会话，P3）
/s/:sid/findings          → 发现
/s/:sid/self-report       → Agent 自报告与实际观测对照（P5）
/s/:sid/agents            → Agent 通信图与 MCP 调用（P6）
/s/:sid/gaps              → 缺口与采集能力
/g/:gid                   → 监控组通信图（P6）
/search                   → 跨会话搜索
/compare?a=&b=            → 多会话对比（P5）
/settings                 → 设置
```

代码中每条路由对应 `ui/src/routes/` 下的一个文件，如 `/s/:sid/timeline` 对应 `s.$sid.timeline.tsx`，页面逻辑在 `ui/src/features/<page>/`，见 [repo-layout](../05-dev/repo-layout.md)。

筛选状态全部编码在 URL query 中（`?f=<filter>&from=&to=`），可以书签或分享给本机的其他用户。

**会话内公共布局**

```
┌───────────────────────────────────────────────────────────────────────────┐
│ AgentWatch ▸ s-7k2m "claude 重构登录" ●录制中 18:42   [停止] [导出▾]     │
├───────────────────────────────────────────────────────────────────────────┤
│ 概览 │ 时间线 │ 进程 │ 文件 │ 网络 │ Agent │ 发现(4) │ 缺口(0)                         │
├───────────────────────────────────────────────────────────────────────────┤
│ 🔍 [ 筛选表达式，如 kind:file path:~/.ssh/**              ] [E1][E2][E3][S][I]│
│ ▁▂▅▇▃▂▁▁▂▆█▅▂▁▁▁▂▃▂▁   ← 时间密度条（可拖选时间范围，红色区段=缺口）         │
├───────────────────────────────────────────────────────────────────────────┤
│                       （页面主体）                          │ 详情侧栏        │
│                                                          │ （选中记录时）  │
└──────────────────────────────────────────────────────────┴─────────────────┘
```

- 筛选栏和时间密度条在会话内的所有页面之间**共享**，切换标签页时保留。
- 录制中的会话，顶栏和概览每 3 秒重读一次会话与概要；会话自己结束（程序退出）后顶栏变为「已停止」、「停止」按钮消失，各页计数重读一次，之后不再轮询。概览在首次采样写入之前，进程数写「等待首次采样」，缺口行写「录制中，到目前没有记录到采集缺口」，不写「0 进程」。
- 「导出▾」：JSONL、CSV（压缩包，每表一个 CSV，文件名 `*.csv.zip`）、Markdown。桌面窗口里由外壳弹出系统「另存为」对话框，写入用户选的位置后在按钮旁提示「已保存到 <路径>」；浏览器里是普通下载。失败在按钮旁用中文说明，不跳页。
- 新建会话页「采集能力」：采到的类别列为带证据徽标的标签；没采的类别按原因合成一句「没采：文件、网络、DNS（这个模式下没有运行对应的采集器）」，与设置页一致，不再写「不可得：当前运行模式不支持采集此信息」。冒号、列表分隔符按语言取（中文「：」「、」，英文 ": " ", "）。会话列表在有录制中的会话时每 3 秒重读，程序退出后该行自己变成「已停止」。
- 设置页「立即清理」只给管理员：非管理员时按钮带 `disabled` 属性、不发任何请求，旁边写「需要管理员权限」及原因；管理员先 dry run 列出将删除的会话数，确认后才删除。
- 「新建会话」的命令框与工作目录框是非受控输入，提交时读取；重渲染不会把旧值写回输入框（桌面窗口里受控输入曾把 `sleep 60` 吞成 `leep 60`）。
- 详情侧栏显示以下内容：
  - 全部字段，每个字段旁边带字段级证据徽标；
  - 来源和佐证来源；
  - 按钮：「前后 10 秒」、「只看此进程」、「只看此子树」、「复制为筛选」。

**组件**：会话表格、磁盘用量指示、筛选器、行内操作（重命名、固定、删除、导出）。

**交互**
- 勾选两个会话后可以点「对比」。对比页是 S 级需求，放在 P3 之后做。
- 已被保留策略清理的会话以灰色行显示，内容为“已清理”。
- 进程、↑/↓、发现、缺口取列表回复里每行的 `stats`，与概览是同一个计数，两处数字一致。网络没采时 ↑/↓ 写「没采」（同概览）；后台没给某个数（如库里没有发现表）时写「–」并悬停提示去概览看，不写 0。
- 状态列带文字：「● 录制中」「○ 已停止」，固定的会话另加 📌。

**组件**：KPI 行、采集能力条、发现摘要、Top 域名、Top 目录、Top 命令。

**规则**
- KPI 中的字节数和计数，只要有一部分来自 S 级或覆盖到缺口时段，就加 `≈` 前缀，并在悬停时解释原因。
- 没有任何发现时，显示“在已观测范围内未发现满足规则的活动”，并附上缺口数。**不得**显示“安全”。
- **「没采」与「没有记录」**：类别是否采集以会话的 `collectors[].capabilities` 为准（见 [api-and-cli](api-and-cli.md)）。某类只被列为 NA 时，KPI、Top 表、文件页、网络页、进程页的对应列一律写「没采」（整页为「没采：本版本不采集…，这里没有数据，不代表没有发生」），**不得**写「没有记录」或 0。没有任何采集器描述能力时写「采集范围不可得，不能确认采集完整」。缺口行在有没采类别时写「没有记录到采集缺口 · 没采：…」，**不得**只写「缺口：无」。

### 3.4 时间线 `/s/:sid/timeline`

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 类别: [☑进程][☑文件][☑网络][☑DNS][☑HTTP][☐Agent][☐IPC][☐RPC][☑发现][☑缺口]  密度[合并▾] │
├────────────┬──────┬─────────────────────────────────────────────────────────┤
│ 10:01:02.11 │ E1   │ ▶ proc  bash(5101) → cat ~/.ssh/id_rsa                      │
│ 10:01:02.11 │ E1   │ 📄 file  cat(5120) 读 ~/.ssh/id_rsa  412 B  [敏感:ssh-keys]    │
│ 10:01:05.08 │ E1   │ 🌐 dns   node(4412) api.example.com → 203.0.113.10              │
│ 10:01:05.10 │ E1   │ 🔗 net   node(4412) → api.example.com:443  ↑5.2KB ↓3.1KB       │
│ 10:01:05.12 │ E2   │ ↔ http  POST https://api.example.com/v1/messages  200  5.0KB  │
│ 10:01:05.10 │ 推测 │ ∴ 读取敏感文件后 3.1s 内有外发（无内容级证据） [查看依据]   │
│ ░░░░░░░░░░░ 缺口 10:03:10–10:03:12 linux.ebpf 丢失 1,204 条 file 事件 ░░░░░░░░░░░░ │
└────────────┴──────┴─────────────────────────────────────────────────────────┘
```

**组件**：类别开关、虚拟列表、缺口横幅行、详情侧栏。

**交互**
- 「密度：合并」模式下，同一进程在 1 秒内对同一目录的连续只读访问折叠为一行，如“读取 src/ 下 37 个文件”，可以展开。
- 点击任一行打开详情侧栏。「前后 10 秒」会把时间范围设为该记录 ±10 秒，并清除类别筛选，用于实现 REQ-05.4。
- 推测行永远带「查看依据」，点击后高亮引用的记录。
- 会话活动时支持「跟随最新」，数据来自 SSE `/live`。
- 右键任一事件可「追溯来源」，打开委托链路面板（见 §3.12）。

### 3.5 进程树 `/s/:sid/processes`

```
┌──────────────────────────────────────────────────────┬──────┬──────┬───────────┐
│ 进程                                                │ 文件 │ 写/删│ ↑/↓       │
├──────────────────────────────────────────────────────┼──────┼──────┼───────────┤
│ ▾ claude (4412)  node .../claude-code/cli.js   18m   │ 1.2k │ 0/0  │ 2.0M/2.1M │
│   ▾ bash (5101)  bash -c "cat ~/.ssh/id_rsa"    0.1s │ 3    │ 0/0  │ –         │
│       cat (5120)  cat /home/u/.ssh/id_rsa  exit 0     │ 1 ▲  │ 0/0  │ –         │
│   ▸ bash (5230)  bash -c "npm install"  → npm → node  │ 1.9k │ 840/2│ 0.1M/45.9M│
│   ▸ node (5130)  mcp-server-filesystem             │ 210  │ 0/0  │ –         │
└──────────────────────────────────────────────────────┴──────┴──────┴───────────┘
```

**显示规则**
- 展开时统计列显示进程自身的数据，折叠时显示含后代的汇总。
- exec 链用 `→` 显示。
- 进程行上的标记：
  - `▲` 表示子树内有敏感访问；
  - Agent 进程带 Agent 图标；
  - 归属中断的位置显示 `⇢ dockerd（会话外）`。
- 进程名取 `exe_name`（`process_images.exe` 的文件名）。采集时读不到可执行文件路径（权限不够或进程已退出）显示「名称不可得」，悬停说明原因，不显示「?」。
- 顶部筛选框按进程名或 PID 筛选；筛选时搜整棵已加载的树，折叠的子树也算。
- 本版本没采的类别（文件、网络）对应列显示「没采」。

**交互**
- 右键菜单：只看此子树、复制命令行、在时间线中定位。
- 快照生成的进程（`how=snapshot`）带 S 徽标。

### 3.6 文件 `/s/:sid/files`

- **视图切换**：列表 / 目录树（按目录聚合访问数，形式为类 treemap 的可展开树）。
- **列**：时间、进程、操作（读 / 写 / 创建 / 删除 / 改名 / 执行）、路径、打开次数、读字节、写字节、证据、敏感标记。
- **快捷筛选**：「敏感」「写入」「删除」「项目目录外」「失败的打开」。其中「项目目录外」指 cwd 之外，对发现越界访问很有用。
- **不可得显示**：字节列显示灰色「不可得」，悬停时显示原因。不显示 0。

- HTTP 请求展开后显示：方法、完整 URL（已脱敏）、状态码、请求和响应的 body 字节数、白名单请求头。

### 3.8 发现 `/s/:sid/findings`

- **列表**：按严重度和时间排序。每条显示以下内容：
  - 模板渲染的完整句子；
  - 证据徽标、命中次数、首次和最后时间；
  - caveats，如“此时段存在缺口”；
  - 依据记录列表，可点击跳转。
- **内容匹配证据**单独分组显示，并展示匹配分块数和覆盖率。
- **筛选**：规则、证据等级、严重度。
- **用户操作**：可以给发现标记“已确认 / 忽略”，写入 `findings.user_state`。这个字段属于 P3 的存储迁移。

### 3.9 缺口与采集能力 `/s/:sid/gaps`

- **上半部分**：本会话的采集器列表，内容来自 `sessions.collectors`。每个采集器列出它提供的事件类型及证据等级；本平台不可得的能力也列出，并附上原因。
- **下半部分**：缺口表，列为时间范围、采集器、类型、影响类别、数量、说明。点击一行跳转到时间线对应的时段。

### 3.10 设置 `/settings`

| 分区 | 内容 | 权限 |
|---|---|---|
| 存储 | 体积上限、保留天数、当前占用、「立即清理」 | 管理员 |
| 隐私 | 脱敏规则（内置规则逐条列出、只读，来自 `GET /config` 的 `builtin_redaction_rules`，每条显示中文说明、悬停看正则；可以增加自定义规则，按正则表达式匹配，预览与后台一致）、敏感路径规则、请求头白名单 | 管理员 |
| 代理 | 默认是否启用、拒绝时的行为、CA 状态（指纹、创建时间、「轮换 CA」） | 管理员 |
| 采集器 | 各采集器的**运行状态**（来自 `GET /doctor` 的 `collectors`，后台采样循环实际报告的状态：进程轮询「运行中（全机采样 + N 个会话）」/「已停止」，内核采集器「本版本未接入」），以及每个采集器能采哪些类别；不显示配置表里的原始开关名 | 查看：所有人；修改：管理员 |
| 规则 | 已加载规则列表、启用/停用 | 管理员 |

### 3.11 跨会话搜索 `/search`

输入自由文本或筛选表达式，结果按会话分组显示。典型用法是“哪些会话碰过 `~/.aws/credentials`”。

每条命中显示类别、来源行文字（文件路径或可执行文件路径）、时间和证据等级，点开跳到该会话时间线前后各 10 秒。后台没给时间时显示「–」，跳转不带时间范围；没给文字时才显示「记录 #id」。进程名可以搜到（轮询采集器存下的可执行文件路径进全文索引）。

### 3.12 Agent 通信 `/s/:sid/agents`、`/g/:gid`

设计见 [inter-agent-communication §8](inter-agent-communication.md#8-cli-与-ui)。

```
┌ 节点（按角色着色） ── 边：实线 E1 · 点划线 E2 · 虚线 E3/I；线宽 = 字节 ─────────────┐
│  [claude · primary] ──1.2 KB──▶ [mcp-server-fs · mcp_server]                     │
│         │ spawned (E1)                                                            │
│         └──▶ [subagent · sub_agent]                                               │
├ MCP 调用（按 server / 工具分组）──────────────────────────────────────────────────┤
│  mcp-server-fs · read_file × 3   未启用 --mcp-tap 时：工具名不可得                │
│    ▸ 10:01:02 tools/call  1.2 KB → 3.4 KB  展开：该次调用期间 server 子树事件     │
└───────────────────────────────────────────────────────────────────────────────────┘
```

**规则**
- 边的线型表示证据等级，不得只用颜色区分。点击边打开依据记录。
- 不显示任何参数或结果内容。
- 未启用 `--mcp-tap` 的会话，MCP 列表顶部固定提示“工具名不可得：未启用 --mcp-tap”。
- 时间线右键「追溯来源」打开委托链路面板：整条链的等级取最弱一跳，显示在顶部；措辞用 `delegation.chain` / `delegation.ambiguous`。

## 4. 可访问性与性能目标

- 全部操作都可以用键盘完成：`/` 聚焦筛选，`j`/`k` 上下移动，`Enter` 打开详情，`Esc` 关闭。
- 证据等级不只靠颜色区分，徽标上始终带文字。
- 性能目标：
  - 会话含 100 万条记录时，筛选响应在 300 ms 内。这是 REQ-05 的要求，由 API 侧索引保证。
  - 首屏在 1 秒内完成。
